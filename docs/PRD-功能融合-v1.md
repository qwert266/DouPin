# 豆拼 DouPin — 功能融合 PRD v1

> 撰写人：产品经理 许清楚
> 时间：2026-07（v1）
> 定位：**自用 / 小范围使用**，不商业化，纯本地，不引入新依赖（iOS 17+ / SwiftUI / SwiftData）
> 竞品调研结论由需求方提供，本 PRD 直接采信，不再重复调研。

---

## 1. 产品目标

**一句话**：把 AI豆仓的「库存管理 + 图纸处理」能力与 PIXDOU 的「灯板引导」能力融合进豆拼，补齐库存/图纸处理两个死穴，同时把已有的「行引导灯板」深化为差异化王牌。

**三个正交目标**：

1. **补库存短板**：建立"色号库存 → 图纸用量预估 → 缺色提示"的最小闭环，让用户拼之前就知道豆子够不够。
2. **补图纸处理短板**：让任意一张大图能被拆板、限色、合并配色、对比原图，并能导出可打印的 PDF——把"从网图到能上板拼"的全链路补齐。
3. **强化差异王牌**：把行引导灯板升级为「行/列/区域引导 + 分色过滤 + 自动前进」，做到竞品做不到的引导体验；模板库从 15 扩到 50+。

**成功标准（自用场景，定性为主）**：
- 上传一张 100×100 大图后，能一键拆成 N 块 29×29 板，且知道每块用哪些色、每种色缺多少。
- 开工前 10 秒内能判断"这张图现在的库存能不能开拼"。

## 2. 目标用户与核心场景

**用户画像**：豆拼现有用户本人 + 少数同好（小范围），使用智能拼豆灯板（A950），iPad/iPhone，离线使用。

| # | 场景 | 具体描述 | 涉及功能 |
|---|------|---------|---------|
| S1 | **开拼前的备料** | 在小红书刷到一张心仪的像素图，想拼，但不确定家里的豆子够不够。导入图纸 → 看消耗预估 → 发现"某色差 120 颗" → 心里有数，先补豆再开工 | 图纸导入、消耗预估、库存 |
| S2 | **大图拆板** | 想拼一张 90×120 的大图，手上有 4 块 29×29 的板。把图拆成 12 块（含跨板对齐提示），逐块上板拼，拼完一块再拼下一块 | 拆板、自动对齐提示 |
| S3 | **边拼边导** | 坐在灯板前拼一块 29×29 的图，手机连灯板，进入行引导：当前行全亮、下一行微亮，想只看红色豆子时切分色过滤；拼完本行点"下一行"，进度自动打卡 | 行引导、分色过滤、进度打卡 |
| S4 | **库存录入与维护** | 拆了一盒新豆子，想快速把 295 色里常用的几十个色号录入库存。支持逐条加，也支持粘贴一段"色号+数量"文本批量导入 | 库存录入、批量导入 |
| S5 | **图纸归档** | 图纸攒到几十张，用状态筛选已经不够了，想按"动漫/风景/猫咪"文件夹或标签归类，找图时直接进文件夹 | 文件夹/标签管理 |
| S6 | **导出线下拼** | 想打印出来对着拼（不连灯板），需要一张带网格线、色号标注、图例的 PDF，A4 分页打印 | PDF 导出 |

## 5. 交互细节定义

### 5.1 库存录入

- **逐条添加**：点「+」→ 弹出色号选择器（295 色板，可按色系/搜索定位）→ 选色号 → 输入数量 → 保存。可连续添加。
- **批量导入**：粘贴多行文本，每行形如 `A1 500` 或 `A1,500` 或 `A1 500`。
  - 解析规则：行内 `色号`（Mard 编号，如 A1/H7/GB1）+ 分隔符（空格/逗号/制表符）+ `数量`（整数）。
  - 冲突处理：若该色号已有库存，弹窗询问「累加 / 覆盖 / 跳过」。
  - 解析失败的行高亮并提示"第 N 行无法识别"，允许修正后重试。
- **库存查看**：列表按色号顺序（A→Z 系列）排列，显示色块 + 色号 + 数量；顶部搜索支持按色号或颜色名模糊匹配。

### 5.2 消耗预估

- 入口：图纸详情 → 「消耗预估」。
- 结果表三列：`色号 | 需要 | 现有 | 差额`；差额为负（不够）标红，为正标绿。
- 顶部汇总：`总需豆量 / 库存总豆量 / 缺色种数`。
- 「缺色清单」按钮：只显示不够的色号及缺口，可一键复制为文本。

### 5.3 拆板

- 入口：图纸详情 → 「拆板」。
- **参数**：
  - 板尺寸：默认 29×29（可改，如 16×16 / 20×20 / 自定义 W×H）。
  - 拆分方向：先行后列。
  - 重叠/对齐：可选「无边缝（严格切分）」或「保留重叠行（相邻板对齐用，默认 0 重叠）」。
- **结果**：生成 N 块子图，每块编号（如 R1C1、R1C2…）。
  - 每块预览 + 该块用色清单。
  - **自动对齐提示**：每块边角显示"右接 R1C2 / 下接 R2C1"，并在拆板结果页用缩略图拼板图展示整体布局，标出每块位置。
- 拆出的子图可**单独保存为图纸**（便于逐块上板拼 + 逐块打卡）。

### 5.4 图纸尺寸 vs 板尺寸分离

- 上传时两个独立参数：
  1. **图纸尺寸**：图片像素化后的行列数（如 20×20）。
  2. **实际拼板**：目标板尺寸 + 图纸在板上的偏移位置（如 29×29 板，图纸放左上角 / 居中）。
- 分离后：空白区域视为"空格"（不点灯、不计豆量），引导时自动跳过。
- 目的：满足"小图也能用 104 板拼，并决定图纸在板上哪个位置"。

### 5.5 限色 / 合并相近色 / 替换配色

- **限色**（已有增强）：选择目标色数（64/48/32/24/16），把图纸颜色量化到调色板的 N 个代表色。
- **合并相近色**：滑杆设置颜色距离阈值 → 预览合并结果（相邻色被归为一个代表色）→ 确认应用。
- **替换整套配色**：点某色号 → 选新色号 → 全图该色号整体替换（带撤销）。
- 三者均**可撤销**（复用现有 40 步撤销栈）。

### 5.6 原图对比模式

- 仅对「照片转图纸」来源的图纸可用（需保留原图引用）。
- 编辑时顶部切换「对比」→ 左右分屏：左原图、右当前像素图，双指缩放**联动同步**。
- 可切换"叠加半透明"模式。

### 5.7 多指缩放 + 框选

- 双指捏合缩放，最大放大到单格占据可点区域（便于精细改）。
- 长按进入「框选模式」→ 拖出矩形 → 底部弹出操作：填充当前色 / 清空 / 替换为某色。

### 5.8 PDF 导出

- 导出内容：网格线 + 每格色号（可开关）+ 底部图例（色号↔颜色）。
- 分页：当图纸超过一页，按 A4 尺寸自动分页，每页带页码和"第 X/Y 页"。
- 导出与现有 PNG 导出并列，不替换。

### 5.9 灯板引导（深化）

- **方向切换**：行引导 / 列引导 / 区域引导（P1）。
- **区域引导**：在图纸上框选矩形 → 灯板只点亮该区域内的豆子。
- **进度自动前进**：设置项「自动前进」开启后，检测当前行/列已全部打卡则自动跳到下一行/列。
- **分色 + 方向组合**（P2）：先选色，再选行/列。

### 5.10 文件夹 / 标签

- **文件夹**：一级文件夹（不做多级嵌套，降低复杂度）；新建/重命名/删除；图纸可移动进文件夹。
- **文件夹内上传**：在文件夹页直接「+」导入图纸，自动归入当前文件夹（解决竞品痛点 2）。
- **标签**：一个图纸可打多个标签；标签页展示所有标签，点标签筛选。
- **排序**：文件夹/图纸长按拖动排序（P2）。

## 6. 数据模型调整建议（SwiftData @Model）

> 现有实体：`Pattern`（唯一主体，承载图纸+进度+作品）。以下为增量建议，描述字段即可。

### 6.1 Pattern（扩展字段）

| 字段 | 类型 | 用途 |
|------|------|------|
| `sourceImageData` | `Data?` | 保存照片转图纸的**原图**（JPEG），支持原图对比模式 |
| `folderId` | `UUID?` | 所属文件夹 |
| `tags` | `[String]` | 标签数组 |
| `boardWidth` | `Int` | 实际拼板宽（默认 = width） |
| `boardHeight` | `Int` | 实际拼板高（默认 = height） |
| `boardOffsetX` | `Int` | 图纸在板上的水平偏移 |
| `boardOffsetY` | `Int` | 图纸在板上的垂直偏移 |
| `sortOrder` | `Int` | 排序序号（拖动排序用） |
| `parentPatternId` | `UUID?` | 若为拆板子图，指向原图 |
| `tileIndex` | `String?` | 拆板编号（如 "R1C2"） |

> `cells`/`placed`/`width`/`height` 等核心字段不变；`boardWidth=0` 时视为等于图纸尺寸。

### 6.2 新增实体

**PatternFolder（文件夹）**
- `id: UUID`（唯一）
- `name: String`
- `sortOrder: Int`
- `createdAt: Date`
- 关系：一对多 → Pattern（通过 `folderId` 弱引用即可，避免 SwiftData 关系复杂度）

**BeadStock（库存，每个色号一条）**
- `id: UUID`（唯一）
- `colorId: Int`（1…295，对应 BeadPalette）
- `quantity: Int`（现有数量）
- `threshold: Int?`（缺色预警阈值，可选，默认 0）
- `updatedAt: Date`

**TileSplit（拆板结果记录，可选，P1）**
- `id: UUID`
- `sourcePatternId: UUID`
- `boardW: Int` / `boardH: Int`
- `tileRefs: [UUID]`（各子图 Pattern 的 id 列表）
- `createdAt: Date`

> 说明：库存也可设计为单条 `Inventory { entries: [StockEntry] }` 聚合，但**一色号一记录**更简单、查询更快，推荐用 `BeadStock`。
> 颜色距离/合并阈值等**算法参数不进模型**，属于编辑期临时状态（内存态即可）。

### 6.3 迁移

- 全部新字段给默认值（`folderId=nil`、`tags=[]`、`boardWidth=0`），SwiftData 轻量迁移可自动完成，无需自定义 MigrationPlan。
- 新增实体直接加入 Schema，老数据不受影响。

## 9. 附：相对竞品的定位结论

- **我们比 PIXDOU 强**：行/列/区域引导 + 分色过滤 + 自动前进，比"逐颗点亮"节奏友好得多 → **作为核心卖点深化**。
- **我们比 AI豆仓弱**：库存管理与图纸处理生态 → **本 PRD 的 P0 主攻方向**。
- **不追的**：竞品的社区/市集/云/硬件扩展/商业化 → 自用场景全砍。
